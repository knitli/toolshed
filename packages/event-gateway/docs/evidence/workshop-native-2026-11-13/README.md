# Workshop native bounded evidence — 2026-11-13

These are exact copies of the reviewed local receipts and one-read snippet source. The receipts are synthetic observer outputs: their `chainLength` and `receiptDigest` fields are reported values, not independently verified cryptographic receipt chains. Request and order IDs are opaque identifiers; the signed requests were revoked after each run. No authorization secrets are included.

The idle and busy trials each observed one canonical read and a bounded callback, then verified the hook remained off and the order was revoked. The busy receipt also records that the original operation completed unchanged before its deferred callback. Its `modelTurnLimitSecondsEach` records a 120-second per-turn bound; the idle `modelTurnLimitSeconds` records a 120-second run bound. These are observer-reported/operator guards, not verified platform-enforced caps. Running the snippet normally emits a self-contained idle fixture declaring `async function executeCode(env, id = "PLACEHOLDER_EXACT_CALLBACK_ID")`; paste it into Workshop’s `executeCode` slot and replace only the callback-id placeholder. The self-check calls that emitted entry as `executeCode(env, callbackId, logger)` with a fake read binding. It checks the function’s behavior, not Workshop’s host dispatch or environment injection. Adapt the note and ACK literals inline for a busy fixture. `--self-check` also parses and validates both receipts; it does not establish live production qualification.

These results do not establish Event Runtime v2 lifecycle ACK, task completion, full E5 qualification, or broad rollout/load qualification.
