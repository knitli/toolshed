# Private Docker SDK adapter spike

This spike replaces the SDK's native-process callback with a fixed Docker-backed `spawn(options)` facade. The public factory is `createDockerAdapter({ root, mode, sessionId? })`; it returns `{ spawn(options), settle() }`. The facade exposes Node streams as both `stdin`/`stdout` and `stdinWritable`/`stdoutReadable`, plus `killed`, `exitCode`, synchronous `kill(signal): boolean`, and standard event methods. It intentionally has no PID.

`spawn(options)` only accepts the absolute `${root}/NEVER-EXECUTED-claude` sentinel, `cwd === root`, and a matching canonical `--session-id UUID`. It never invokes that command or forwards `options.env`. Docker receives a scrubbed environment, a fixed Unix socket endpoint, and a newly created mode-0700 config directory under the physical mode-0700 owned root.

The container is created from the pinned local Python image with `--pull=never`, `-i`, the fixed mode/session command, a single read-only bind of `root/fixture`, no network, UID/GID 65532, all capabilities dropped, no-new-privileges, read-only root, private IPC and PID namespaces, bounded memory/CPU/PIDs, a 16 MiB `/work` tmpfs, disabled logs/restart, and no auto-remove. The adapter validates the fixture SHA-256, exact random container name and label, full container ID, image, mounts, limits, and isolation before starting it. Ownership (exact full ID, generated name, and label) is established before full policy validation so an owned container with bad settings can still be safely cleaned up; an identity mismatch is never adopted or mutated. Port mappings are rejected for any nonempty object or array.

Creation errors are treated as potentially dispatched: recovery queries only the exact random name, establishes exact ID/name/label ownership before full policy validation, and cleans up only an adopted owned ID. `settle()` is idempotent and waits for launch/attach completion, inspected `Running=false`/`Pid=0`/actual `ExitCode`, forced removal, exact ID and name absence, and matching daemon identity before/after. SDK kill requests use one bounded SIGTERM/SIGKILL path against the validated container ID. Cleanup stages run independently and their errors are combined with the primary failure. Child-process close events are recorded when each Docker CLI is spawned; `exitCode` alone does not prove stdout/stderr closure. If any owned Docker CLI's close cannot be confirmed, the private Docker config directory is retained. CLI output is drained while a shared 64 KiB budget limits retained stdout and stderr. Protocol stdin/stdout are capped at 64 KiB per frame and 2 MiB combined before forwarding to the SDK parser.

The trusted `child_process.spawn` function is copied from its live ESM builtin binding at adapter module initialization. This preserves the captured callable if a later SDK-native-entrypoint guard patches the builtin export and calls `syncBuiltinESMExports()`. A boolean-only offline probe verifies this mutation boundary without exposing or invoking the captured callable. The fake backend is exported as `createDockerAdapterWithFakeBackend` only for this private test file. The shared CLI-output collector has an offline test seam so the production retention budget can be exercised without spawning Docker. `node test-adapter.mjs` uses in-memory Docker control-plane and attach streams; it does not start Docker, the SDK, a native CLI, a provider request, or a network connection.

The current review-fix candidate passed both `node --check` commands and 26 fake-only groups covering startup buffering, success/early-terminal/EOF/abort, duplicate kill, PID 1 ignoring TERM with bounded SIGKILL escalation, kill-before-CID, create-response loss recovery including invalid owned policy, attach exit while the container still runs, shared CLI output retention, sticky transport failure, observed and unconfirmed CLI close, cleanup after earlier-stage failures, no-PID facade, command timeout, daemon mismatch, wrong identity, unconfirmed removal, and combined input overflow. The tests use only in-memory Docker control-plane and attach streams.

Fixed fixture source SHA-256: `f5d7ae681045266d2b9f2d806beee8b07c0f527f4feffd523037076c3d9d4cd6`.

The current review-fix candidate has not run against Docker or the actual SDK. Historical attempt3 evidence qualifies only its archived source hashes. The live local socket/image and container inspect/cleanup behavior remain unqualified until the frozen integration review authorizes that step.

`stdin.write()` and `stdin.end()` reserve frame and combined budgets before Node queues payloads, including corked and pre-attach writes. String byte lengths are checked before allocation; `_write()` charges receipt counters once. Tests cover queued overflow, callback/encoding forms, empty and repeated end, and combined input/output limits. Five causal mutants restore the original bypass, remove queued-end admission, double-count receipts, remove callback drainage, or allocate oversized strings early; all fail the regression checks.
