# Native terminal public query artifact

This review bundle packages a bounded public terminal query and paired TUI bridge spike. It does not activate an installed client, Start, selection renewal, provider execution, cloud settlement, or production binding.

Apply the patches in order to the frozen 66-file terminal-history selected source closure plus the hashed app-server test-module supplement described below:

1. `01-public-query.patch`: public protocol and app-server query (8 files).
2. `02-tui-terminal-query.patch`: paired TUI query bridge (4 files).
3. `03-generated-protocol.patch`: generated JSON, TypeScript and compressed exports (6 files).
4. `04-generated-sdk.patch`: subsequent Python SDK regeneration (1 file, 12 added lines).
5. `05-terminal-query-recovery.patch`: exact-Start gating before recovery and recovery of a missing InputRecorded anchor when a terminal receipt already exists (3 Rust files).

The first three patches preserve the original frozen 18-file proof. The fourth is a separately qualified generation follow-up; it was not part of the 375-test run. The original tested and final hashes are retained independently. `finalSelectedSourceClosureSha256` records stage04, changing only the Python generated file within the 71-file selected closure. `repairedSelectedSourceClosureSha256` records stage05 after the three-file repair. The original 18-file maps, payloads and four-stage replay remain unchanged.

The replay required the original 66-file history closure plus the existing app-server test module `codex-rs/app-server/tests/suite/v2/mod.rs`. Its base hash was checked against the frozen history bytes and the frozen-history baseline Git object recorded in `proof/replay.json`. This is local baseline provenance, not independent upstream authentication. The original four patches passed `git apply --check`, were applied in a disposable directory, and produced the recorded stage04 hashes. A subsequent fresh replay of all five patches passed the same checks and produced all 71 repaired final hashes, recorded separately in `proof/repair-replay.json`. No native executable ran during artifact packaging.

## Evidence and limits

`proof/source-qualification.json` records the earlier native proof: 313 protocol, 23 app-server, 38 TUI tests, and one RPC scenario (375 total). It includes causal checks and wire/bridge observations. These are recorded results, not tests rerun by this bundle. Seven tested files differ from the final formatted source. `tested-to-final.diff`, `clippy-source-delta.diff`, and the tested/pre-format hashes preserve that distinction. The retained Clippy edit removes a redundant Copy clone in one new TUI test. The original proof records successful formatting equivalence; native tests did not run after fix/format.

`proof/sdk-generation.json` closes the original missing-wheel SDK generation gate using the exact locked 27-package tool environment. Generation exited successfully, changed only `sdk/python/src/openai_codex/generated/v2_all.py`, and left the original 18 frozen files and dependency lock unchanged. It preserves source log/cache digests and sanitized environment details without bundling tool caches or raw logs.

`proof/repair-qualification.json` records the separate repair run: **27 scoped tests passed** (25 app-server unit tests and two public stdio RPC tests), with two actual pre-fix assertion failures. The repaired query rejects a missing exact Start before recovery locks/history reads, and recovers the canonical InputRecorded anchor for a Started row even when an immutable terminal receipt already exists. The RPC fixtures replay through fresh server processes without loading threads or changing selection/rollout history. This proof does not relabel or rerun the original 375-test evidence.

The repair's native-tested and native-final 71-file maps use the **pre-SDK** Python generated bytes. Stage05 composes the previously qualified SDK04 bytes only for artifact replay; the repair did not regenerate or test those SDK bytes. The repair's scoped Clippy fix changed no source. `repair-tested-to-final.diff` records the formatting-only differences in two Rust files; native tests did not run after fix/format. The sanitized repair proof retains the frozen source manifest digest and log hashes; raw local paths, source copies and logs remain outside this bundle.

## Offline artifact check

Run `python3 verify.py` from this directory. It checks bounded inventory, payload hashes, source-map consistency, patch structure and recorded replay metadata. It does not execute native code or repeat the historical test run. Optional `--source-root` verifies the composed stage05 71-file closure against a supplied source tree, reverses SDK04 and the repair formatting delta to check the repair's native-tested bytes, then reverses repair05 to recheck the original tested/pre-format chain; `--frozen-base-manifest` authenticates the original external history manifest by its pinned digest. The sibling `terminal-history-spike/manifest.json` supplies the immutable parent source closure.

The manifest and verifier are review roots, not signatures. Hash consistency detects damage or contradictory evidence; it cannot independently attest a producer or establish test execution. Raw logs and private source trees are not included. Review any source changes and complete the remaining qualification gates before integration or activation.
